### 二、找到「廉价感」的真正来源：Win11 亚克力自带一层系统乳白（关键）
- 逐层量像素定位：整窗压纯黑桌面 = `#262729`，但**实机**截图里图片口却是 `#B4B9BE`（浅灰）。
  差的这一截不是我们画的 —— 是 `ACCENT_ENABLE_ACRYLICBLURBEHIND` 在 Windows 11 上额外叠的
  那一层**系统乳白**。它不跟着我们的令牌走，所以整窗怎么调都像一块发白的塑料板。
- 改成**首选 `ACCENT_ENABLE_BLURBEHIND`（纯模糊，系统不掺色）**，亚克力只作兜底：着色 /
  加厚 / 高光全部由我们画。同一张深色壁纸下，图片口从 `(78,109,129)` 降到 `(25,60,81)` ——
  桌面真的上来了。自测加了守门：`attach()` 里第一个被请求的必须是 `BLURBEHIND`。

### 三、大面板不铺面：整窗与图片口的「奶」来自我们自己的柔光
- 整窗原来画一撮 `GLASS_SPECULAR` 热点：几万像素的板子上，那撮热点扩散开来半径几百像素，
  = 铺满半屏的奶白。**整窗与图片口现在 `gloss=False` + `specular=False`**，只沿**边缘**给光。
- 图片口原来默认开着 `gloss`，光位转到右下时整块内容区被一层 0.30 的白扫过（实测 +29/255）。
  关掉后图片口在任意光位下的像素完全一致（实测一致到 0）。

### 四、让玻璃「活着」：指针光 / 焦散 / 环境光 / 各向异性（本轮重点）
- **指针光**（`liquid.LightField`）：整块界面**只有一个光源**。指针在哪，光就从哪来 ——
  镜面热点朝光源偏移、受光边跟着转、焦散绕到背光侧。每 33ms 只跟 30%，所以是「跟过来」
  而不是瞬移（那点延迟就是液体的黏度）。
  - 更新走**应用级事件过滤器**，不靠事件冒泡：按下的按钮会把鼠标移动吃掉（要处理「拖出去
    取消」），靠冒泡光会卡在按钮上。
  - 每一块玻璃 `follow_light(self)`，光一挪就重绘。实测 PySide6 在接收者销毁时会自动断开
    连接（`weakref` 验证：widget 被回收、emit 不再回调），所以缩略图上那个**删了又建**的
    删除键不会攒连接、也不会被信号吊住。
- **边缘焦散**（`GLASS_CAUSTIC`）：光穿过玻璃，在**背光侧**聚成一道细亮弧（1.4px、内缩 2px），
  跟着光位绕边 —— 真玻璃的边缘就有这圈。
- **受光边薄光**（`GLASS_EDGE_GLOW` / `_WIDTH = 26px`）：大面板不能铺面，但完全不给光就是一块
  死玻璃；所以只给**边**，而且宽度是**像素**（放大窗口不会跟着摊成一片）。
- **内容环境光**（`AMBIENT_*`）：新图进来 → 缩到 8×8 取均色 → 保色相、饱和度 ×0.55、
  明度夹在 0.45~0.85（雪景洗不白、夜景压不暗）→ 以图片口为中心 850ms 淡入；再来一张先退到
  45% 再染上去（呼吸）。它压在文字区薄面**之下**，所以再花的照片也吃不掉字：自测按最暗的
  借色重算，最差底仍 4.90:1。
- **按下各向异性**（`GLASS_SQUASH`）：`PressSpring` 从「等比缩 3.5%」改成**纵向压 3.5%、
  横向鼓 1.9%** —— 等比缩放只是图标在缩，压扁 + 鼓起才像一滴液体被指尖按下去。

### 八、光更小、更顺：临界阻尼弹簧取代指数插值
- 用户看过一版之后只留一句：「光要很小，要很流畅」。上一版的光靠**指数插值**（每 16ms 跟
  16%）：够顺，但起步那一下是**跳着**加速的（首帧就跟着整体比例的固定步长走），末尾又会在
  接近目标时**贴上去**，观感上像「先弹一下、再啪地吸住」。这版换成**临界阻尼弹簧**。
- **`LightField`（`liquid.py`）从「位置 + 每帧插值比例」改成「位置 + 速度」**：目标一动就
  给系统一个速度，`_advance(dt)` 用**解析解**前推
  `e(t) = (e0 + (ė0 + ω·e0)·t)·e^(-ωt)`，落定即清零速度。指数插值按帧乘比例，**掉帧就会
  走成一段一段**（帧越稀，每步越大）；弹簧按**真实 dt** 积分，解析解在任何步长下都稳，
  **欧拉法在掉帧时会发散**，所以不用欧拉。dt 上限 100ms。
- **令牌（`styles.py`）**：删 `GLASS_LIGHT_EASE`，新增 `GLASS_LIGHT_OMEGA = 14.0`（固有频率，
  ω 越大越「紧」）；心跳 `LIGHT_TICK_MS` 16 → **8ms**（比屏幕刷新还密，每帧拿到的光位都新鲜）；
  落定阈值 `GLASS_LIGHT_SETTLE` 0.0015 → **0.0008**（尾巴收得更干净）。
- **光整体收小一档**：`GLASS_CAUSTIC` 0.13 → **0.09**；`GLASS_EDGE_GLOW` 0.10 → **0.07**、
  宽度 `GLASS_EDGE_GLOW_WIDTH` 20 → **12px**（宽度是像素，放大不糊）；受光边正中那朵沿边的
  柔光 `GLASS_EDGE_HOTSPOT` 0.06 → **0.045**、半径 `GLASS_EDGE_HOTSPOT_R` 0.35 → **0.22**
  （压小 = 光只在边上走一小段，不做成整条亮带）。
- **实测（80×40 探针图，同一次采样）**：新版受光区 **468 个像素**（上一版 934）、最深
  **8px**（上一版 16）、峰值 **22/255**（上一版 35）—— 面积减半、深度减半、强度再降一档。
- 自测 **135 → 140 项**，新增 §17 五条：光**起步最柔**（首步 < 最大步 1/3）、**不过冲**
  （单调逼近，不越过目标）、**末段收住**（末步 < 最大步 1/20）、**光很小**（受光带深 ≤ 12px
  且亮点像素 ≤ 600 / 共 3200）。**140 项，0 失败**。
- 文档同步：`docs/03-UI设计规范.md` §2 光影表换成 `GLASS_LIGHT_OMEGA / LIGHT_TICK_MS = 14.0 / 8`
  与新的焦散 / 薄光 / 柔光值，「受光边薄光」那行 20px → 12px，§1 主线补「光要小而顺」，
  §2.1 把「每 16ms 跟 16%」改写成弹簧（起步从 0 加速、不过冲、末尾收住）。

  （`_resume_after_drag` 与材质一起恢复），其余靠 `BACKDROP_TICK_MS = 140` 的心跳兜底。
- 实测（本机 150% 缩放）：四角是干净的大圆弧、玻璃那圈细亮边跟着弧走、背后是真模糊，而窗口
  外的桌面依旧**锐利**。CPU：稳定后 13~19% 单核（抓屏 ~7ms + 糊 ~3.5ms + 重绘 ~4.6ms，
  7 次/秒），最小化后 0%。第一次量到 100% 是启动那一瞬的瞬态。
- **顺手收掉两笔旧账**：① 指针光再「收」一档（`GLASS_LIGHT_OMEGA` 14 → **11**、
  `GLASS_LIGHT_SETTLE` 0.0008 → **0.0002**）—— 用户说末尾那一下还有点「咔」；
  ② 左侧卡片里的镜面热点改成**像素半径**（原来按边长 0.55 倍算，176px 的卡片上铺开 ≈ 97px，
  等于糊掉半个面）—— 用户要的是「很小的一粒光针」（§十再收到 10）。
- 自测 **140 → 144 项**：§3 换成新规矩（自己画 20 / 系统那档 8；`backdrop=True` ⇒ DWM 模糊
  关掉、圆角让开；自绘底暂停期间不抓屏；自绘底画在最底层），§17 补「镜面热点是像素半径」。
  **144 项，0 失败**。

### 十、光针收成一粒 + 拖动时桌面跟着走（本轮收口）
- 用户回看：「左边小方框内的指光针变小一点，要很小」。上一步把镜面热点从「按边长 0.55 倍」
  改成像素半径 26 已经小了很多，但**在 176px 的卡片上仍是一朵 52px 的光晕**。做法：先把卡片
  单独离屏渲染出来做半径对比（`work/shots6/spec_probe.py`：26 / 18 / 12 / 8 并排放大 3 倍），
  26 是一朵糊在图标下方的光、8 是一粒干净的光点 —— 取中间值 **`GLASS_SPECULAR_R = 10.0`**。
  同时把这条写成一个**不变量**塞进自测：光针半径必须 **≤ 卡片的圆角**（`RADIUS_CARD`），
  否则「一粒光针」迟早又会长回一片光。
- **拖动时背后那层桌面要跟着走**：上一轮为了不卡，拖动期间直接 `suspend()` 掉抓屏 —— 窗口动了、
  背后的桌面不动，玻璃就成了「贴在一张旧照片上」。改成**限速跟随**：`moveEvent` / `resizeEvent`
  走 `Backdrop.refresh_throttled()`，距上次抓成功不足 `BACKDROP_MOVE_MS = 70` 就跳过
  （抓一次 ~7ms，贴着每帧抓会掉帧），停手后 `resume()` 补一张最新的。实测拖动跟手、无卡顿。
- **「投过来的背景还是高清」→「没之前那版自然」→「我就要那版」**：背后那层糊，连着挨了
  三轮实机反馈，最后定在**还原自绘底之前那版（DWM 亚克力）的厚度**上。
  ① 先把「缩 6 倍糊 2 遍」量出来 —— **σ≈4px（≈2.6 逻辑像素）**，几乎等于没糊，难怪壁纸的
  线条、桌面图标还看得清（「还是高清」）。② 拍到 20 倍 3 遍（σ≈16px）后又被说**不自然**：
  不只是**糊多少**，还有**核的形状** —— 纯 Qt 的「缩小再放大」最后一步只有双线性插值，
  缩到 1/20 再拉回来 20 倍，画面就是**一片片斜坡**（等距折痕），像盖了层马赛克；而
  「之前那版」之所以自然，是因为那层是 DWM 画的真高斯（糊得厚，但核是圆的）。
  ③ 定版：**真高斯**（Pillow `GaussianBlur`，半径即 σ）**σ = 16 物理像素（≈10.7 逻辑像素）**
  —— 厚度对齐亚克力那档，过渡连续无折痕。先缩一半再糊省一半 CPU（24ms → 6.4ms）。
  自测阈值从一个下限改成**区间 16..45px**：下限防「高清」、上限防「糊成一片」；兜底路径
  （无 Pillow 时的 `_box_blur`，缩 20 倍糊 3 遍）单独设门槛。
  顺带核实了一次「进程没了」：`QImage(bytes, ...)` 不是野指针（PySide6 会持有那个缓冲，
  压测 400 轮 + 逼回收都对）—— 不是崩溃，是被关掉了。
- **「移动时流畅一点就好了」**：拖动时那层底每 70ms 要重抓一张，而「抓 + 糊」原来是**内联
  在 UI 线程**里跑的。按 60Hz 的鼠标节奏量了 120 步：**25 步超过 8ms、最大 19.9ms（p95 18ms）**
  —— 每 70ms 掉一帧，手感就是卡。改成把「抓 + 糊」丢进 `QThreadPool`（`Backdrop.request` /
  `_CaptureTask`），UI 线程只剩 `_adopt` 那 0.5ms（QPixmap 只能在 UI 线程建，贴图这一步
  必须留下）。同一次拖动复测：**每步平均 0.65ms、最大 1.30ms、没有一步超过 8ms**。
  同一个 `Request` 只放一张在外面（`_busy`）：抓回来时窗口位置早变了，攒着排队没意义。
  功能侧也核过一遍（拖动 1.5s：发起 19 次、采用 31 张、异常 0）—— 底确实在跟着走，不是冻住。
- 顺手修掉一条**擦边通过**的旧用例：「镜面热点朝着光源」原来按**角**取样，半径 26 时
  其实是靠余光摊到角上才勉强通过（左上角 30 vs 右下角 28）；半径收到 10 立刻暴露。
  正解是按**受光边**取样（对角线光位下锚点在顶边 / 底边的**中点**，不是角）。
- 自测 **144 → 150 项**（+3 限速跟随与心跳区间、+1 模糊强度门槛、+1「抓+糊在工作线程里」；
  另重写 1 条擦边通过的旧用例）。**150 项，0 失败**。

## 风险与阻塞
- **像素级位移折射仍然做不到**（如实说明，不假装）：`rdev/liquid-glass-react` 靠浏览器
  `backdrop-filter` 采样**背后**的像素做位移；Qt 桌面端拿不到那层像素（窗口背后的桌面由 DWM
  在窗口之外合成）。能保真移植的是**光影结构**（边缘光 / 焦散 / 光泽 / 色差 / 内阴影）+ 现在
  这套指针光与内容染色。
- 环境光只能取「均色」，图案类的照片（例如大片天空 + 一小块红）会被平均掉；这是刻意的取舍
  （宁可少染，也不要把玻璃变成花玻璃）。
- 指针光会让整窗在指针移动时以 ~30fps 重绘；实测离屏绘制开销极小（<1ms/帧），实机手感待确认。
