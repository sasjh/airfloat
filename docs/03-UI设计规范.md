# 03 · UI 设计规范（毛玻璃版）

> 依据：Apple 设计原则（材质 / 字体 / 间距 / 层级 / 布局 / 交互），技能 `apple-design`。
> 落地：`src_py/ui/styles.py` 是**唯一令牌来源**（材质 / 颜色 / 字体 / 间距 / 圆角），
> `src_py/ui/main_window.py` 只消费令牌，不写字面量；
> 矢量图标在 `src_py/ui/glyphs.py`，窗口级亚克力在 `src_py/ui/glass.py`，
> 液态玻璃的光影原语（`paint_glass` / `PressSpring` / `GlassSurface`）在 `src_py/ui/liquid.py`。
> 液态玻璃光影参考 `rdev/liquid-glass-react`（MIT），取舍见 §2.1。
> 旧 Electron 版 `src/renderer/` 已废弃，不再作为规范参照。

## 1. 设计原则

简洁、直观、无冗余；主色**淡蓝**；信息层级清晰；只做必要控件。

补充（毛玻璃版新增，五条主线）：

- **低透 + 局部加厚**：整窗只着色 **13%**（`GLASS_TINT_ABGR`），桌面 / 壁纸的色与影真的
  从玻璃底下上得来 —— 这才叫「透」。整窗透着，字就不能再靠整窗兜底，所以**有字的区域
  各自垫一层薄面**（`SIDEBAR_FACE` / `TOPBAR_FACE` / `STATUSBAR_FACE = 0.52`）把该区的
  亮度下限抬回 AA；**图片口这种大块内容保持真透**。通透感来自「大面积真透 + 小面积厚度」
  的对比，不是把整窗调实 —— 整窗调实就是把桌面挡回去（那才是「糊」）。内容面
  （`GLASS_SURFACE = 0.72`，照片瓦片 / 文件名条）仍是实的那一档：内容要压得住背后杂色。
  着色每往下压一档，薄面就得往上补一档 —— 这是一对，动一个必须动另一个（自测按令牌实时重算）。
- **结构靠厚薄，不靠描边**：分区之间不画硬线，也不给分区套边缘光 —— 侧栏 / 顶栏的「更厚」
  只体现为一层更亮的薄面。图片口是**裸透**：它自己不画任何东西（没有托盘洗、没有柔光池、
  没有描边），空态提示直接压在玻璃上（见 §3「空态」）。
- **玻璃只做点缀**：只有「能摸的东西」套液态玻璃光影 —— 窗口外壳、按钮、菜单、浮层、
  悬停 / 按下反馈。**内容是内容**：照片瓦片、设备行一律安静（低透面 + 发丝线），
  不跟主操作抢戏。玻璃铺满 = 没有层级 = 糊。
- **渐变光影出声，分割线闭嘴**：顶栏受光 → 内容居中 → 状态栏下沉，一档亮、一档中、
  一档深，层次由光来讲；区域之间不画硬线。整窗那层「铺满上半屏的光泽带」已撤掉
  （那是奶膜，是糊的直接来源），光集中给顶栏一条受光带。
- **对比度按最差底校准**：文字不按白底校准，而按「材质最暗处」**逐层**压出来 ——
  玻璃着色 `BG #EAF4FF` @13% 压纯黑桌面 = `#1E2021`，再叠文字区薄面 = `#939494`，
  再叠窗口底部内阴影 = `#8F9090`。所有文字按它达标（≥ 4.5:1）。
- **层级靠三者协同**：字号 + 字重 + 字距共同建立层级，不靠单一字号拉大。
- **用邻近性表达从属**：同组元素紧凑（4–8px），组与组之间拉开（20px）。
- **状态必须可见**：控件外观要如实反映真实状态（圆钮的蓝/灰 = 开/关、菜单勾选 = 当前项）。
- **让玻璃「活着」**：整块界面只有**一个光源**，它跟着指针走（`GLASS_LIGHT_*`）；光穿过
  玻璃，在背光侧聚成一道**焦散**（`GLASS_CAUSTIC`）；收到的照片把自己的颜色借给玻璃一点
  （`AMBIENT_*`）；按下时纵向压、横向鼓（`GLASS_SQUASH`）。光有延迟、颜色会呼吸、按下
  像一滴液体 ——「有生命」和「一张贴纸」差的就是这几样。
- **只借系统一层模糊，不借它的颜色**：整窗走 `ACCENT_ENABLE_BLURBEHIND`（**纯模糊**）——
  Windows 11 的亚克力还会额外叠一层系统乳白，那层白不跟着我们的令牌走，桌面再透也上不来
  （正是「廉价」的直接来源）。着色 / 加厚 / 高光全部由我们画；拿不到模糊时逐级降级，不假装。
- **细节克制**：所有材质 / 光影强度都是 `styles.py` 里的**具名令牌**，组件里不准出现
  `lit=0.9`、`wash(0.06)` 这类字面量 —— 一个数值只有一处定义，才谈得上「统一」。

**三档材质分工**（这是「透」与「不糊」的解法）：**整窗**负责**透**（13% 着色，桌面真的
上得来）；**文字区薄面**负责**看得清**（0.52 浅面，把该区亮度下限抬回 AA）；**控件玻璃**
负责**像玻璃**（0.30~0.54 半透、背后模糊整片透上来）。三者各司其职，不互相将就 ——
为了保文字对比去把整窗调实，是拿「透」换「不糊」，两头都输。
**大面板不铺面**：整窗与图片口调用 `paint_glass` 时 `gloss=False` 且 `specular=False` ——
一块几万像素的板，任何一层柔光铺开都是一片奶白（= 糊）。大面板的玻璃签名只在**边缘**
（镜面边缘光 + 焦散 + 受光边那圈薄光）。

凹槽环玻璃（`liquid.paint_well_glass`，§2.1）：不铺浅色面，只画一个「凹槽」——
半透的槽底 + 顶内阴影 + 底内受光 + 一圈发丝环 + 环外一条弱落影。

| 令牌 | 值 | 含义 |
|---|---|---|
| `RING_FILL_TOP` / `RING_FILL_FLOOR` | `1.22` / `0.82` | 槽底渐变：顶部（凹进去那侧）最实、底部最浅 |
| `RING_TOP_SHADE` | `0.26` | 顶内阴影（凹） |
| `RING_BOTTOM_LIGHT` / `RING_LIGHT_TOP` | `0.34` / `0.80` | 底内受光：只贴边那一条（0.80 落在字形盒之下，不洗字形） |
| `RING_EDGE_TOP` / `RING_EDGE_BOTTOM` | `0.70` / `0.95` | 发丝环上缘 / 下缘（下缘最亮 = 反光） |
| `RING_SHADOW` / `RING_INSET` | `0.22` / `1.0` | 环外那条弱落影 / 凹槽内缩 1px |

指针光 / 焦散 / 内容环境光 / 按下的各向异性（§2.1 用）——「让玻璃活着」的四个机关，
一条都不许在组件里写死：

| 令牌 | 值 | 含义 |
|---|---|---|
| `GLASS_LIGHT_REST` | `(-0.72, -0.72)` | 静息光位（左上）：没有指针时的设计约定 |
| `GLASS_LIGHT_EASE` / `LIGHT_TICK_MS` | `0.30` / `33` | 每 33ms 只跟 30% —— 光「跟过来」而不是瞬移 |
| `GLASS_LIGHT_SHIFT` | `0.35` | 镜面热点：从光源侧边缘朝玻璃中心挪这个比例 |
| `GLASS_CAUSTIC` / `GLASS_CAUSTIC_INSET` | `0.20` / `2.0` | 背光侧那道焦散细弧的强度 / 离边缘多远 |
| `GLASS_EDGE_GLOW` / `GLASS_EDGE_GLOW_WIDTH` | `0.16` / `26.0` | 受光边内圈的薄光：大面板只给**边**给光（宽度是**像素**，放大不糊） |
| `GLASS_SQUASH` | `0.55` | 按下的各向异性：纵向压 3.5%，横向就鼓 1.9% |
| `AMBIENT_MIX` / `AMBIENT_ALPHA` / `AMBIENT_SETTLE_MS` | `0.55` / `0.13` / `850` | 内容环境光：借多少饱和度 / 那层光多强 / 染多久 |
| `AMBIENT_DIP` | `0.45` | 再来一张图：先退到当前的 45% 再染上去（呼吸，而不是换色） |
| `AMBIENT_SPREAD` | `0.90` | 染光半径 / 窗口长边（图片口附近最浓，到边缘淡没） |
| `AMBIENT_VALUE_FLOOR` / `_CEIL` | `0.45` / `0.85` | 借色的明度夹口：雪景洗不白、夜景压不暗 |

「发送」圆钮的槽底（强调色）阶梯，**每一档都按最亮底**（纯白壁纸）验过其上白箭头：
`SEND_WELL 0.90`（3.25:1）/ `SEND_WELL_HOVER 0.94`（3.84:1）/ `SEND_WELL_PRESSED 0.96`（4.47:1）。

**窗口级实现**（`glass.py`，纯 ctypes，不依赖 Qt）：整窗**首选**
`SetWindowCompositionAttribute(ACCENT_ENABLE_BLURBEHIND)` —— 只借系统一层**干净**的高斯模糊；
亚克力（`ACCENT_ENABLE_ACRYLICBLURBEHIND`）只作兜底，因为它在 Windows 11 上会额外叠一层
系统乳白，把我们的着色与光影一起糊掉。`mode` 反映实际结果 —— `blur`（首选）/
`acrylic`（兜底）/ `solid`（都不支持时退化为不透明浅蓝底，保证文字永远可读）。
透明区用 `SetWindowRgn` 圆角裁剪 + `DWMWA_WINDOW_CORNER_PREFERENCE` 对齐。**移动期间不降级**
（见 §7）：模糊一路都在，桌面才会在玻璃底下跟着走。只有缩放期间才
`suspend()/resume()` —— 边长每帧都在变，模糊跟不上的错位比降级更显眼。

### 2.1 液态玻璃（Liquid Glass）

参考 `rdev/liquid-glass-react`（MIT）：它用 SVG 位移图对**窗口背后**的内容做折射。
浏览器有 backdrop-filter / SVG filter，能直接采样背后的像素；Qt 桌面端**拿不到** ——
窗口背后的桌面由 DWM 在**窗口之外**合成（亚克力模糊本身就是 DWM 画的），Qt 读不到那层像素。
所以像素级位移折射无法移植，**能保真移植的是光影结构**（`liquid.paint_glass`，一层一层叠）：

| 图层 | 画的是什么 | 对应参考实现 |
|---|---|---|
| 底色 | 上亮下暗的半透明填充 | `blurAmount` / `saturation` |
| 表面光泽 | 顺着**光轴**、从光源那侧铺开、到中线前淡没的白 | 表面反光 |
| 镜面热点 | 光源那侧一朵软椭圆高光（跟着指针走） | 光源在左上 |
| 内阴影 | 按下时顶边压暗 | 按下态 |
| 边缘色差 | 冷 / 暖描边各偏 1px | `aberrationIntensity` |
| 边缘焦散 | 背光侧一道细亮弧（光穿过玻璃聚成的） | 玻璃边缘的亮弧 |
| 镜面边缘光 | 沿光轴渐变描边（光源侧亮 → 另一侧暗） | 位移造成的边缘亮边（`displacementScale`） |
| 受光边薄光 | 光源那侧内圈一条 20px 亮带（只给边，不给面） | 边缘高光 |

- **只画光、不铺底**：`tint=None / alpha=0` 时内部完全透明，绝不挡住背后的真实模糊；
  浅材质面 `alpha=0.72` 是「低透」而不是实底。`lit` 统一缩放高光强度（`lit=0` ⇒ 整块透明），
  取值一律走 §2 的光影强度表，组件里不写 `lit=` 字面量。
- **整窗不铺面、也不点热点**：`AirFloatWindow.paintEvent` 里每一层都是 `gloss=False` +
  `specular=False` —— 铺满上半屏的那层白是「奶膜」，一撮热点在几万像素的板子上扩散开来
  也是一片奶白（= 糊）。整窗的光只留：边缘色差 + 焦散 + 镜面边缘光 + 受光边薄光 +
  两处文字区薄面（顶栏 / 状态栏）。
- **四次落笔，顺序有讲究**：`paintEvent` 先画折射彩边 → 再铺**内容环境光**（压在薄面**之下**，
  不许拿可读性去换）→ 再铺两处文字区薄面 → **最后**才压上受光边薄光与那圈 1px 镜面边缘光
  （含焦散）。薄面若后画，会把玻璃的签名（那圈细亮边）盖掉 —— 玻璃就不像玻璃了。
- **一个光源**（`LightField`）：指针在哪，光就从哪来；`aim_at()` 只把**目标**挪过去，光场
  自己每 33ms 跟 30%，直到贴住 —— 那点延迟就是液体的黏度。所有玻璃（整窗 / 卡片 /
  按钮 / 菜单行）都 `follow_light()`，所以它们的高光方向永远一致：**同一间屋子，同一盏灯**。
- **结构分区不套边缘光 / 色差**（`GlassSurface`）：侧栏 / 图片口是铺满的，全出血矩形上画描边
  就变成硬分割线，与「区域之间不画硬线」冲突 —— 它们只保留底色 + 顶部光泽。
- **回弹**（`PressSpring`）：按下**纵向压 3.5%、横向鼓 1.9%**（各向异性 —— 等比缩放只是图标
  在缩，压扁 + 鼓起才像一滴液体被指尖按下去），松手用 `OutBack` 弹回（对应 `elasticity`）；
  尊重系统「减少动态效果」，关闭时直接落终态。
- **内容环境光**（`AMBIENT_*`）：新图进来 → 取那张图的均色（缩到 8×8 再平均）→ 保色相、
  饱和度乘 `AMBIENT_MIX`、明度夹在 `FLOOR..CEIL` → 以图片口为中心铺一层极淡的柔光，
  850ms 淡入（再来一张先退到 45% 再染上去 = 呼吸）。它压在薄面**之下**，所以再花的照片
  也不会把字吃掉（自测按最暗的借色重算过 AA）。
- **容器不再自己铺底色**：侧栏 / 图片口 / 图标按钮 / 「发送」的底色都改由 `paintEvent` 画，
  QSS 一律 `background: transparent` —— 任何底色都会把玻璃盖掉。
- **删除键的遮罩片取 0.58**：它压的是**任意照片色**，0.58 才能保证白字形在纯白照片上仍有
  4.74:1（≥ 3:1 是图标底线）；更轻的玻璃会把白字形洗掉。
- **凹槽环玻璃**（`paint_well_glass`）：第二种玻璃形态，用在「发送」圆钮上。它和 `paint_glass`
  分工不同 —— **不铺浅色面**，只画一个凹槽：槽底（上深下浅）+ 顶内阴影 + 底内受光 +
  一圈发丝环 + 环外一条极轻的落影。立体感全靠光，所以描边细（1px）、阴影弱；也因为它
  不铺面，背后的真实模糊能整片透上来。`tint` 是槽底座色（缺省深色洗，发送键传强调色），
  `fill` 是槽底的实度 —— 两者都要跟对比度一起调。

### 2.2 玻璃出现在哪里（点缀清单）

「玻璃效果仅做点缀」落到代码上就是一张名单 —— 名单外的表面一律安静：

| 表面 | 材质 | 说明 |
|---|---|---|
| 窗口外壳 | 纯模糊 + 焦散 + 边缘光 + 受光边薄光 + 色差 + 顶栏受光带 | 唯一的「大面积玻璃」：只沿边给光，绝不铺面 |
| 顶栏图标按钮（文件夹 / 关闭） | 控件玻璃片（`light` = 0.54）+ 悬停 / 按下 / 回弹 | 能摸的东西，给足反馈 |
| 「发送」圆钮 | 强调色**凹槽环玻璃** + 白色向上箭头 | 主操作，全界面唯一的饱和玻璃；只有箭头，不留文字 |
| 弹出菜单 / 菜单行 | 深色玻璃 + 行悬停片 | 浮层，浮在内容之上才配叫玻璃 |
| 缩略图删除键 | 深色遮罩片 → 悬停错误色 | 压在**任意照片**上，所以要够实（0.58） |
| 隔空投送圆钮 | 强调色实心 + 一层小透镜高光 | 只压一层，多一层就像贴纸 |
| 隔空投送卡片 | 控件玻璃（`CONTROL_GLASS*`）+ 悬停 / 按下 | 能摸的东西，走半透那一档 |
| 侧栏 | 文字区薄面（`SIDEBAR_FACE`）；`GlassSurface` 不套边缘光 / 色差 | 结构分区：靠「更亮一档 = 更厚」分层次 |
| 图片口 | **什么都不画**：没有托盘洗、没有柔光池、没有描边（裸透） | 大块内容保持真透；空态提示直接压在玻璃上 |
| 照片瓦片（缩略图） | **不套玻璃光影**：低透面 + 发丝线 | 内容是内容，不该有光泽和色差 |
| 设备行 | 透明；悬停 `CHIP_ALPHA`、选中强调色实底 | 列表是内容 |

## 3. 配色

文字色按**最差底 `#8F9090`** 校准（而非白底）。它是逐层压出来的：
`#EAF4FF` @13% 压纯黑 → `#1E2021`，叠文字区薄面（0.52）→ `#939494`，再叠底部内阴影 → `#8F9090`：
（自测把这三层全部从令牌实时重算，动了着色 / 薄面 / 底影任何一个都会在那里被重新校验。）

| 用途 | 色值 | 实测对比度 |
|---|---|---|
| 材质基色 | `#EAF4FF` | 淡蓝底（玻璃 13% 压纯黑 = `#1E2021`；叠薄面与底影 = `#8F9090`） |
| 浅材质面 | `#FFFFFF` | 卡片 / 按钮叠加层基色 |
| 主文字 | `#1B222C` | 最差底 5.00:1 |
| 次要文字 | `#232A34` | 最差底 4.52:1 |
| 强调色 | `#2E6CB0` | 其上白字 5.40:1 |
| 强调色·图标底 | `#1568C8` | 圆钮上白色字形 5.46:1 |
| 关闭态圆钮 | `#6B7280` | 其上白色字形 4.82:1 |
| 成功（文字） | `#0B2A1B` | 最差底 4.82:1 |
| 空态提示（亮字） | `#F2F7FF` | 压在裸玻璃上：**不垫底**，靠 24/700 的字号与字重立住层级（见下） |
| 成功填充 | `#1E7D5C` | Toast 底，白字 5.07:1 |
| 错误填充 | `#B3403C` | 其上白字 5.62:1（悬停 `#9C3532`） |

悬停 / 按下：`ACCENT_HOVER #2A61A0` / `ACCENT_PRESSED #24568F`。

**约束**：新增颜色必须标注实测对比度；文字色一律 ≥ 4.5:1，图标（非文字）≥ 3:1。
`PRIMARY #4A90D9` 与旧成功色 `#3EB489` 对比度不足，已降级为装饰 / 替换。
底色最差处是「纯黑桌面 + 文字区薄面 + 底部内阴影」——浅色桌面上实际对比度更高，
此基线是最保守下界。三层的参数都取自 `styles.py` 的令牌，`test_ui.py` §13 直接按令牌
重算这个最差底，所以调透明度/洗色/底影时会立刻暴露对比度是否还达标。
**空态提示是刻意不按这条走的唯一一处**：图片口是整窗最透的地方，裸玻璃上深色文字只有
1.02:1 —— 压不住。参考图（iOS「Clear」面板）给的做法是**亮字直接压在墙上**，靠字号 / 字重
立层级，而不是给文字加一块底。加底会在玻璃上浮出一层灰（深色桌面下尤其显眼，正是「图片口
中间那片光晕」的来源）。所以空态只有**一档不透明度**（`HINT_TEXT`，大标题 24/700 与副行
13/500 同色），周围不加底 / 描边 / 光晕 —— 亮字压在亮壁纸上天然低对比，这是刻意的；
§13 里那条断言写的就是这件事：亮字**不该**有第二档颜色，也不该有衬底。

## 5. 间距与圆角

- **间距**：4pt 网格（`SPACE_1..6 = 4 / 8 / 12 / 16 / 20 / 24`）。
  侧栏内边距 12；「卡片 → 分组标题」20px；「标题 → 列表」4px；列表项之间 2px。
- **圆角阶梯**（`RADIUS_*`）：窗口 **8** → 卡片 / 缩略图 **14** → 控件 / 菜单行 **10** →
  弹出菜单 **18**。不再出现 7/16/12 等随手值。
  窗口的 8 不是随手取的：模糊由 DWM 画、只认 `DWMWA_WINDOW_CORNER_PREFERENCE` 的系统圆角
  （100% DPI 下 8px，随 DPI 缩放，**应用无法指定更大值**），窗内自绘半径必须与它同心，
  否则圆角处会出现两条不同心的弧。
- **几何常量**（`main_window.py`）：
  - 窗口：`DEFAULT_WINDOW = (400, 560)`、`MIN_WINDOW = (340, 440)`；**无 GUTTER**（玻璃即窗口，不为投影留白）。
  - 侧栏宽 158；顶栏 44；状态栏 36；图标按钮 26；「发送」圆钮 ⌀34（箭头图形占 0.56）。
  - 卡片 134×132，圆钮直径 44；缩略图 84×62 + 18px 文件名；网格间距 8；
    删除键 20px（内缩 4px）；菜单宽 196、行高 44、内边距 6、投影留边 14。

## 6. 布局（两栏）

```
┌──────────────┬──────────────────────────┐
│ 顶栏：品牌 · 本机别名       📁  ✕（拖动区）  │
├──────────────┼──────────────────────────┤
│ 设置（左）    │  图片口（右，较宽）         │
│  ─ 隔空投送卡片│  缩略图网格（每张带删除键）  │
│    （圆钮+取值）│ （空态：提示文字）         │
│  ─ 附近设备    │  （可拖入发送）           │
├──────────────┴──────────────────────────┤
│ 状态栏：将发送到 / 计数 / 进度    [发送]      │
└─────────────────────────────────────────┘
```

- **左栏第 1 行**：隔空投送**模块卡片**（对齐 iOS「隔空投送」模块）——左上角 44px 圆钮
  （开=强调蓝实心 + 白字形；关=灰圆钮），左下角两行：`隔空投送`（cardTitle）+ 当前取值
  `所有人 ⌄`（cardValue）。
- **左栏第 2 行**：「附近设备」列表（别名 + 类型图标），点击选中发送目标。
- **右栏「图片口」**：接收图片缩略图网格（列数随窗口宽度自适应）；空态是一行大标题

  tooltip 与拖入时的虚线层，不占版面。

## 7. 交互

| 交互 | 行为 |
|---|---|
| 点卡片圆钮 | 切换 enabled（`setEnabled`）；圆钮蓝/灰即时反映开/关 |
| 点卡片其余部分 | 打开「可接收对象」菜单（`Qt.Popup`） |
| 菜单选项 | 接收关闭 / 仅限联系人 / 所有人，**选中项前置对勾**；选「接收关闭」= 关开关但**记住**上次模式 |
| 点菜单外 / Esc | 关闭菜单（Qt.Popup 原生行为） |
| 点选设备 | 选中发送目标（强调蓝实底 + 白字） |
| 拖图片文件进右栏 | `sendFiles(选中设备, 文件路径)`；拖入时显示虚线提示层 |
| 拖缩略图出浮窗 | `airfloat.dragOut(filePath)` 触发系统级文件拖拽 |
| 缩略图右上角 ✕ | 从收发列表移除该图（悬停变红；同步清掉待发包） |
| 拖窗口边 / 角 | **八向缩放**（6px 热区；系统缩放优先，失败回退手动；最小 340×440） |
| 拖动顶栏 | **自己跟手移动**窗口（`QWindow.startSystemMove()` 在本机返回 True 却纹丝不动，已弃用；玻璃圆角随之重算）；**移动期间不降级材质** |
| 悬停图标按钮 | 浮出一片玻璃（`_GlyphButton` 的 tone）；关闭 / 删除键悬停转错误色 |
| 按下按钮 | 玻璃压进去（内阴影）+ **纵向压 3.5% / 横向鼓 1.9%**，松手 `OutBack` 弹回 |
| 指针在窗口里移动 | **一个光源**跟着指针走（`GLASS_LIGHT_*`）：镜面热点、受光边、焦散与受光边薄光一起挪；每 33ms 只跟 30%，所以是「跟过来」而不是瞬移 |
| 收到新图 | 玻璃被那张图的颜色**借一点**（`AMBIENT_*`，850ms 淡入；再来一张先退 45% 再染上去） |
| 缩放窗口 / 连收多图 | 缩略图重建时旧图先摘除并隐藏，避免与新图叠在一起 |
| 右键 / 📁 | 打开接收目录（`revealCache`） |
| 关闭按钮 / Esc | 关闭窗口（无边框窗口必须给出「出口」） |

**移动 / 缩放的材质处理**：**移动不降级** —— 拖动窗口时模糊一路都在，桌面在玻璃底下跟着走，
这正是「背景跟着动」的观感来源（旧做法一拖就 `suspend()`，窗口当场变成一个没有模糊的透明洞，
文字直接压在生桌面上）。**缩放才降级**：边长每帧都在变，模糊跟不上的错位比降级更显眼，
所以拖拽缩放期间 `material.suspend()`，停手 `RESIZE_SETTLE_MS = 180ms` 后 `resume()`
切回真模糊。窗口几何用 `QSettings` 持久化；最大化时不套圆角裁剪。

## 8. 状态

- 空态、接收中 / 发送中（进度条）、无设备（提示「未发现手机，请确认同一 WiFi」）、错误（Toast）。
- **状态栏互斥**：传输中只显示「进度 + 百分比 + 文件名」，状态提示与接收计数让位；
  传输结束后恢复。
- **Toast**：淡入 + 轻微上浮；成功 / 错误用深色填充保证白字对比度（成功 `#1E7D5C`、错误 `#B3403C`）。

## 9. 无障碍

- 次要文字 / 强调色文字 / 白字填充均 ≥ 4.5:1，图标 ≥ 3:1（基线 = 最差底 `#8F9090`，见 §3）。
- **空态提示是有意的例外**：亮字直接压在裸玻璃上（不带底），亮壁纸下对比度会低于 AA ——
  对齐参考图的做法：层级由 24/700 的字号与字重承担，而不是靠加底（见 §3）。
- 所有可点控件有可见键盘焦点环（含自绘卡片 / 菜单行）。
- 尊重系统「减少动态效果」（`SPI_GETCLIENTAREAANIMATION`）：关闭时动效直接落终态。
- 系统不支持模糊时退化为纯色底，绝不退化成「半透明但看不清」。
- **动效不是可读性的代价**：指针光 / 焦散 / 环境光都只改**光**，不改文字底 —— 环境光那层
  还压在文字区薄面**之下**（自测按最暗的借色重算过：最差底仍 4.9:1）。
- 「发送」圆钮不留文字标签，但有 `accessibleName = 发送` 与 tooltip —— 视觉做减法，
  无障碍不做减法。
